# Step 4 Batch Runner

## Goal

Run Step 4C (LLM extraction) and Step 4D (Markdown rendering) for every
article in `data/index/`, reporting per-article and aggregate token usage.
This is the standard way to process a full corpus once the single-article
pipeline has been validated.

---

## Key Idea

The batch runner is a thin loop over `extract_article_card` and
`render_article_card_file`. It adds:

- **Auto-discovery** of article IDs from `data/index/` (any directory with
  a `parents.jsonl` file).
- **Per-article token tracking** via `DeepSeekClient.usage` —
  prompt tokens, cached tokens, and completion tokens are reported per
  article and summed at the end.
- **Graceful error handling** — a failure in one article is logged and the
  batch continues.
- **Skip logic** — articles with an existing `article_card.json` are
  counted as `skipped` (no LLM call made) unless `--overwrite` is passed.

### Token usage and prompt caching

Each article makes 9 LLM calls. Because the article reading text lives in
the system message (constant across all 9 calls) and only the module
question changes in the user message, the provider's prompt cache is hit
from call 2 onwards. Cache hit rates of 70–99% are typical, reducing
effective input token cost by ~90%.

The summary table shows:

```
Prompt:  1,146,261 tokens  (cached: 887,424 = 77.4%)
```

Cached tokens are typically billed at ~10% of normal input price.

## Inputs

Discovered automatically from `data/index/`:

| Source | Path |
|---|---|
| Parent chunks | `data/index/{article_id}/parents.jsonl` |
| Metadata (optional) | `data/working/{article_id}/metadata.json` |
| Schema | `schemas/article_card.schema.json` |

### Environment variables

| Variable | Default | Description |
|---|---|---|
| `DEEPSEEK_API_KEY` | — | Primary API key |
| `OPENAI_API_KEY` | — | Fallback API key |
| `DEEPSEEK_BASE_URL` | `https://api.deepseek.com` | LLM endpoint |
| `LLM_MODEL` | `deepseek-v4-flash` | Model name |

## How to Run

```bash
export DEEPSEEK_API_KEY=sk-...

# All articles
python pipeline/step4_batch_run.py

# Specific articles only
python pipeline/step4_batch_run.py --article-ids pdf_abc123 pdf_def456

# Re-extract articles that already have a card
python pipeline/step4_batch_run.py --overwrite

# Extract only — skip Markdown rendering
python pipeline/step4_batch_run.py --skip-render

# Custom model or endpoint
python pipeline/step4_batch_run.py --model deepseek-chat --base-url https://api.deepseek.com
```

## Output Format

Each article prints one row as it completes:

```
#     article_id                       status   mods        prompt       cached   completion    calls    time
[1/9] pdf_b984e5bc1768479a             ok       9/9        250,411      194,560       28,341        9   312.4s
[2/9] pdf_16edbbde296287d6             skipped  —                —            —            —        —     0.0s
[3/9] pdf_1f32328f6dffc4c2             failed   —                —            —            —        —   305.1s
      ERROR: TypeError: sequence item 0: expected str instance, dict found
```

| Column | Description |
|---|---|
| `status` | `ok`, `skipped` (card exists), or `failed` |
| `mods` | Modules successfully extracted (e.g. `9/9`) |
| `prompt` | Total input tokens sent to the LLM |
| `cached` | Input tokens served from the provider's prompt cache |
| `completion` | Output tokens generated by the LLM |
| `calls` | Number of LLM API calls made |
| `time` | Wall-clock time for this article |

The final summary aggregates all articles:

```
Summary
  Articles:    7 ok  1 failed  1 skipped
  LLM calls:   63
  Prompt:      1,146,261 tokens  (cached: 887,424 = 77.4%)
  Completion:  154,593 tokens
  Wall time:   2613.1s
```

## Python API

```python
from pathlib import Path
from pipeline.step4_batch_run import discover_article_ids, run_one
from pipeline.step4C_extract_article_card import DeepSeekClient

data_root = Path("data")
client = DeepSeekClient(model="deepseek-v4-flash", api_key="sk-...", base_url="https://api.deepseek.com")

article_ids = discover_article_ids(data_root)
for article_id in article_ids:
    result = run_one(article_id, client=client, data_root=data_root, overwrite=False, skip_render=False)
    print(result.article_id, result.status, result.prompt_tokens, result.cached_tokens)
```
